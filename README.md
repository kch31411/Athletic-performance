# Athletic Performance

체육관 프로그램(HY-FIT / WEIGHT / CARDIO / HYROX)에 대해 **"오늘 몇 kg으로, 몇 개를, 몇 분 안에"** 를
미리 처방하고, 운동 결과를 받아 **내 능력치와 컨디션 추정을 갱신**하는 개인 코칭 엔진.

```
프로그램 이미지 ─▶ data/workouts/*.yaml ─┐
                                          ├─▶ 처방서 (무게 · 목표 RPE · 목표 기록 · 페이싱)
프로필 + 지난 기록 ─▶ 능력치·피로 상태 ──┘            │
        ▲                                             ▼
        └──────── data/logs/*.yaml ◀──── 운동 후 피드백 (실제 무게×횟수, RPE, 기록)
```

## 무엇을 모델링하나

능력치는 한 덩어리가 아니라 **계층적인 잠재 요인**들이다. 각 요인은 "프로필에 적은 수준의 평균적인 사람 대비 몇 %"
(로그 스케일)와 그 **불확실성**을 함께 가진다.

| 영역 | 요인 | 의미 |
|---|---|---|
| 근력 | `str` → `str.pat:<패턴>` → `str.mov:<동작>` | 전신 → 패턴(스쿼트·힌지·런지·수평/수직 밀기·수평/수직 당기기·올림픽) → 동작별 1RM |
| 근지구력 | `end`, `end.pat:<패턴>` | 같은 %1RM 에서 몇 개를 더 하는가 (반복수–강도 곡선의 기울기) |
| 파워 | `str.pat:olympic`, `ana` | 올림픽 리프팅 계열 근력, 짧은 전력 구간의 무산소 여유 |
| 심폐 | `eng`, `eng.mod:<머신>` | 지속 가능한 출력(cal/분). 로잉·스키·바이크·어썰트·러닝별 편차 |
| 복합 수행능력 | `met`, `met.cat:W/G`, `met.dur:short/medium/long` | 메트콘 페이스. 웨이트 위주/맨몸 위주, 길이별 편차 |
| 컨디션 | `cond` + 패턴별 국소 피로 + 전신 피로 | 오늘 하루의 상태. 매일 초기화되고 최근 운동량에 따라 감쇠 |

계층 구조 덕분에 **한 종목의 기록이 관련 종목 추정에도 전이**된다(백스쿼트 기록 → 프론트 스쿼트에 크게,
벤치에는 조금). 처음엔 수준(입문~상급)·성별·체중에서 나온 평균값으로 시작하고, 기록이 쌓일수록 개인값으로 수렴한다.

### 예측 식 (요약)

- **근력 세트**: `무게 = 오늘의 1RM × 1/(1 + (R−1)/k)`, `R = 목표 반복수 + 남길 반복수(RIR) + 세트 누적 피로`.
  `오늘의 1RM = 능력치 × 컨디션 × (1 − 피로 페널티)`. k 는 근지구력 요인(기본 28).
- **맨몸 동작**(풀업·푸쉬업): `체중×비율 + 외부중량` 을 무게로 보고 같은 식을 쓴다 → 연속 최대 횟수, 중량/보조 여부가 나온다.
- **머신**: `출력(T) = CP × (1 + A/T)` (임계 파워 모델). 칼로리 ↔ 시간 ↔ 500m 페이스 환산.
- **메트콘 무게**: 의도 강도(가볍게/중간/무겁게), 총 볼륨, 세트 크기로 %1RM 을 정하고, 같은 기구를 쓰는 동작들 중 가장 약한 동작에 맞춘다.
- **메트콘 기록**: `Σ 반복수 × 사이클시간 × 무게계수 × (1 + 휴식비율(세트난이도))` 에 길이 계수와 복합 수행능력을 곱하고 머신 구간을 더한다.
  세트난이도 = 반복수 / 연속 가능 최대 반복수 → 언제 끊어야 하는지(예: 21 → 12-9)도 여기서 나온다.

### 갱신 (피드백 → 모델)

모든 관측을 "요인들의 선형 결합 + 잡음" 으로 놓고 **칼만 필터**로 갱신한다.

- 근력 세트: `무게 × 횟수 @ RPE` → 그 세트가 뜻하는 1RM. 저반복은 근력 요인을, 고반복은 근지구력 요인을 더 많이 움직인다.
- 너무 쉬웠던 세트(RPE 5 이하)는 "최소 이만큼은 된다"는 **하한 정보**로만 쓴다.
- 메트콘 기록: 실제 사용 무게로 다시 예측한 시간과 비교 → 복합 수행능력·엔진 요인 갱신. 팀 운동은 잡음을 크게 본다.
- 하루의 예측 오차는 **컨디션**(빠르게 변함)과 **능력치**(천천히 변함)가 불확실성 비율대로 나눠 갖는다.
  기록이 많아질수록 하루의 부진은 컨디션 탓으로, 반복되는 부진은 능력치 변화로 해석된다.
- 운동량은 패턴별 국소 피로(반감 약 1일)와 전신 피로로 쌓여 다음 날 처방을 낮춘다. 7일/28일 부하 비도 추적한다.

## 사용법

Claude Code 세션에서 대화로 쓴다(`CLAUDE.md` 에 절차가 있다).

1. 주간 프로그램 이미지를 올린다 → 날짜별 처방서를 받는다.
2. (선택) 운동 전에 수면·근육통·피곤함을 말한다 → 그날 처방이 조정된다.
3. 운동 후 결과를 말한다. 예: "벤치 60kg 10개 4세트, 마지막 세트 RPE 8. 카디오는 14:20, 40kg 썼고 좀 가벼웠음."
   → 예측과 실제의 차이, 갱신된 추정, 바뀐 다음 처방을 받는다.

직접 돌릴 수도 있다.

```bash
pip install numpy pyyaml pydantic pytest   # MCP 서버까지 쓰려면 + mcp
python -m coach plan 2026-11-25
python -m coach review 2026-11-25
python -m coach status
```

## 다른 에이전트와 연동 (MCP)

비서 에이전트 등 외부 LLM 은 MCP 서버(`python -m coach.mcp_server`)의 도구 24개로 이 시스템을 쓴다.
엔진 안에는 LLM 이 없고, 에이전트는 칠판·말을 **단위·id·형식이 강제된 입력**으로 옮기는 일만 한다.
도구 목록, 스키마 원칙, 설정 방법은 [`docs/mcp.md`](docs/mcp.md).

## 한계

- 초기값은 수준별 평균이라 처음 1~2주는 범위가 넓다. 알고 있는 기록(1RM, 최대 풀업, 로잉 기록)을 프로필에 넣으면 바로 좁아진다.
- 메트콘 시간 모델의 사이클 시간·휴식 규칙은 경험칙이다. 개인 편차는 학습되지만, 형식별 구조적 오차는 기록이 쌓이면 손봐야 한다.
- 팀 운동 기록은 파트너의 영향을 받으므로 약한 증거로만 쓴다.
- 의학적 조언이 아니다. 통증이 있으면 처방보다 몸 상태가 우선이다.
